# Show the agent glance on the second status line, not in status-left

The always-on list of agent panes is tmux's second status line (`status` `2`, `status-format[1]`), not a segment appended to `status-left`. It overwrites only tmux's stock second-line text, the centred per-pane index and size that is present in the option and not on screen while `status` is `on`. If that slot already holds anything else, the plugin errors once, says how to point the row setting elsewhere, and stops. It does not hunt for another row. The agent-radar `status-left` segment is removed. The window highlight and the seen mark stay. Which script does that work is not this decision.

A reader would repair the glance by widening `status-left`, or leave the old segment in place beside a new line. Both die. tmux's default `status-left-length` is 10, so the session name consumes the visible left side and the segment never appears. Theme and status plugins own that first line, and the segment cannot be configured out of the clash. Keeping it has no value. A later empty-looking row is not an escape: tmux will not show `status-format[2]` unless it also shows `status-format[1]`, so the stock pane-size line would appear in between. A sidebar is refused. Doing nothing leaves the facts only inside `prefix + a`.

The line ships on, server-global, same audience as the highlight and the navigator. The setting is the default. A command may toggle it without editing the setting, and that command is not the navigator key. A reload or plugin re-source makes the setting win, so a toggle does not survive `source-file`. Off removes the row and returns the terminal to one status line. Off is not a blank second line, and it is not "nothing tracked."

What it prints is the navigator's raw facts, not a new judgment. Default fields are the state dot and `session:window.pane`. Optional fields are only those the navigator already prints: harness, session name, window name, branch, and age. Order is the navigator's, as in `docs/adr/navigator-ordering.md`: unseen-stopped oldest-first, then the middle tier, then seen-stopped. A list that does not fit is cut from the tail, so the unseen-stopped front stays. "Running too long" and "should be stopped" are the operator's deductions. This note does not add those states. A stopped pane still counts: the allowlisted process is there. `CONTEXT.md` treats stopped as "go look," not "finished."

Three empties stay distinct. No allowlisted harness in tmux: the row stays and says so. The facts cannot be read: the row stays and shows an error, and that error must not say none were detected. Turned off: the row is gone. A one-shot message is enough for the occupied-row error. A failed read does not hide the row.

The first status line is untouched. Overwriting a customized `status-format[1]`, showing a later line to dodge an occupied second line, putting the glance back into `status-left`, and dropping the highlight or the seen mark are forbidden. Today those two ride the status-left render, and `docs/adr/poller-self-heal.md` already records that `status off` loses the highlight with that render. With the glance on, its render keeps them on the status-interval cadence. With the glance off, a `session-window-changed` hook keeps them, so they refresh on window switches, not on a timer.

Accepted cost: an install whose second-line format is still stock gains a visible second row on by default, in place of a pane-size format it was not showing. An install that already customized that slot gets one error and no glance until the setting moves. Recovery of a toggle waits on the next reload if the setting is still on. With the glance off, a newly stopped agent's window is highlighted, and a dead poller restarts, only on the next window switch, as with `status off`.

This note does not choose the exact wording of those messages, the toggle command's name, whether off writes the stock pane-size text back, or how the highlight and the seen mark share code with the old segment or the navigator. It does not change detection, the navigator popup, its order, its jump, notify, or sound.

Reopen this if tmux stops using `status` `2` plus `status-format[1]` for a second line, if that slot's stock text is no longer the unused pane-size format, or if a theme or status plugin owns the second line by default. Wanting the glance back in `status-left` is not a trigger.
